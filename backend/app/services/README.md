# services

도메인 기능(카탈로그·활동·다이어리·마이페이지·컬렉션·추천·소셜)의 흐름과 규칙을 구현합니다. 도슨트 답변 흐름은 `docent/`에 있습니다.

| 파일 | 담당 |
| --- | --- |
| `catalog_service.py` | 사조·작가·작품 목록과 상세, 카드 변환 |
| `chat_service.py` | 로그인 대화 저장·조회·초기화·내 대화 목록 |
| `like_service.py` / `follow_service.py` | 작품 좋아요 / 작가 팔로우 |
| `library_service.py` | 열람 기록, 월별 캘린더와 일별 상세 |
| `recommendation_service.py` | 비슷한 작품·맞춤 작품·추천 작가 |
| `diary_service.py` | 감상평 CRUD와 공개 피드. 사용자×작품당 한 편, 하루 개수 제한 없음 |
| `mypage_service.py` | 프로필·비공개 컬렉션·활동·취향 소개 근거 조회 |
| `social_service.py` | 공개 회원 프로필·회원 팔로우·목록 공개 범위 |
| `auto_collections.py` | 최근·자주·작가·월별 감상 기록 묶음 |
| `theme_collections.py` | 사용자별 AI 감성 테마 생성과 DB 캐시 |
| `collection_assistant.py` | AI 취향 소개와 컬렉션 채팅 제안 |

인증은 `core/auth.py`에서 처리합니다. 별도 가입·로그인 서비스는 없습니다. 컬렉션 채팅과 도슨트 제안은 제안만 반환하고, 확정 후 컬렉션 REST 호출로 저장합니다. MCP 도구(`mcp/collection_server.py`)는 같은 컬렉션 저장 서비스를 호출합니다.

## 추천 흐름

1. 최근 좋아요 10점을 시드로 사용합니다. 없으면 최근 열람 5점을 사용합니다.
2. repository에서 가까운 후보 최대 30개를 받아 작가당 1점씩 최대 3점을 고릅니다.
3. 부족하면 팔로우 작가 작품 → 큐레이션 작품 → 나머지 이미지 있는 작품으로 채웁니다. 대체 무작위 순서는 사용자와 서울 날짜로 고정합니다.
4. 추천 작가는 후보 유사도 합산으로 정렬하고 이미 팔로우한 작가를 제외합니다. 부족하면 다른 미팔로우 작가로 채웁니다.

추천 중 임베딩 API를 호출하지 않습니다. 저장된 작품 벡터를 사용합니다.

## 구현 규칙

기존 카탈로그·활동·채팅·추천은 repository를 통해 DB에 접근합니다. 마이페이지·소셜·테마 등은 현재 서비스 내부에서도 SQLAlchemy 쿼리를 사용하므로 수정 시 해당 서비스의 소유권 검사와 트랜잭션도 확인합니다. 커밋·롤백은 세션 의존성이 자동 처리하지 않고 서비스 등 쓰기 작업 코드가 명시적으로 수행합니다. 오류는 도메인 예외 또는 `HTTPException`을 사용합니다. 열람 날짜는 `core/timeutil.py`로 계산합니다.
