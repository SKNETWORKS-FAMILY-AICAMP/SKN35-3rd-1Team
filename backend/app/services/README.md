# services

기능의 흐름과 규칙을 구현합니다. 라우터가 호출하고, repository와 `rag/`를 호출합니다.

## 들어갈 파일

| 파일 | 담당 |
| --- | --- |
| `auth_service.py` | 가입, 로그인 |
| `catalog_service.py` | 작가별·사조별 목록, 작품·작가 상세 |
| `chat_service.py` | 작품 확인 후 `rag/`에 질문 전달, 응답 스키마로 정리 |
| `like_service.py` | 좋아요 등록·취소·목록 |
| `follow_service.py` | 팔로우 등록·취소·목록 |
| `library_service.py` | 열람 기록 남기기, 월별 캘린더, 하루 상세 |
| `recommendation_service.py` | 비슷한 작품, 맞춤 작품, 추천 작가 |

## 추천 서비스의 흐름

1. 사용자의 최근 좋아요 10개를 시드로 가져옵니다.
2. 좋아요가 없으면 대체 경로로 갑니다. 최근 열람 작품을 시드로 쓰고, 그것도 없으면 팔로우한 작가의 작품, 마지막으로 큐레이션 작품(`is_featured`)을 돌려줍니다.
3. repository에서 시드와 가까운 후보 30개를 받습니다. 현재 보고 있는 작품과 이미 좋아요한 작품은 제외된 상태입니다.
4. 작품 추천은 후보를 순서대로 훑으며 작가당 1개씩 골라 3개를 반환합니다.
5. 작가 추천은 후보를 작가별로 묶은 점수에서 팔로우한 작가를 빼고 3명을 반환합니다.

평균 취향 벡터는 만들지 않습니다. 이유와 쿼리는 `docs/db/db-design.md` 5장에 있습니다.

## 규칙

- SQL을 쓰지 않습니다. 데이터는 repository 함수로만 가져옵니다.
- HTTP 상태 코드를 직접 다루지 않습니다. 문제가 있으면 `core/exceptions.py`의 예외를 던집니다.
- 추천 실행 중에는 임베딩 API를 호출하지 않습니다. 저장된 작품 벡터만 사용합니다.
- 열람 날짜(`viewed_on`)는 `core/timeutil.py`로 한국 시간 기준 날짜를 계산해 넘깁니다.
- 서비스 함수는 가짜 repository로 테스트할 수 있게 작성합니다.
