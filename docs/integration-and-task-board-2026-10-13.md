### 먼저 합의할 API 항목 (YOONJUNG·taemin → lsh)

- `GET/PATCH /api/me/preferences`를 후보로 조회·수정 계약을 확정하고 `docs/api.md`에 적습니다. 현재 구현된 경로라는 뜻은 아닙니다.
- DB는 `birth_year`, `gender`, `tone`, `explanation_level`이고 프론트는 `age_range`, `gender`, `explanation_style`입니다. 나이대를 임의의 출생연도로 변환하지 않습니다. 선택형 출생연도로 UI를 바꿀지, age_range 컬럼을 추가할지 먼저 결정합니다.
- tone·explanation_level의 허용 값과 NULL/초기 설정/수정/삭제 처리를 명시합니다. UID·user_id는 요청에서 받지 않고 검증 토큰으로 결정합니다.
- 응답 생성에서 사용자 설정을 조회해 적용합니다. 성별만으로 말투를 추정하지 않고 사용자가 선택한 톤·설명 수준을 우선합니다.

## 실행 순서

1. taemin은 기존 8작가 데이터로 채팅 POST와 저장 연결을 진행합니다. 신규 2작가 검수를 기다릴 필요가 없습니다.
2. lsh의 디자인, YOONJUNG의 설정 계약·API, ju의 검수는 동시에 진행합니다. soohwi는 위 5개만 확인합니다.
3. ju는 검수 제외 동작을 확인한 후 승인한 자료부터 산출물·DB·벡터를 갱신합니다. 임베딩·운영 데이터 변경은 권한 있는 담당자와 실행합니다.
4. YOONJUNG이 실제 로그인 두 계정, 질문→답변→저장→복원→초기화, 프로필 재조회와 품질 질문셋을 확인합니다. lsh는 확정된 API와 최신 프론트를 배포합니다.
5. P1: 잔여 50개 작품 검수, 전체 27개 RAG 질문 품질 평가, 설명 스타일 적용·모바일 마감. P2: CI 자동 검사와 성능/오류 지표 정리. 전체 평가 주관은 YOONJUNG, 검색 오답 조치는 taemin·ju가 맡고 soohwi의 확인 범위는 늘리지 않습니다.

## 검증 기록

- 백엔드 전체 테스트 **275개 통과** (운영 TiDB 대신 가짜 저장소·메모리 DB/Chroma 사용).
