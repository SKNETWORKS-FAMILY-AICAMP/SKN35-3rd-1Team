# AI 취향 테마 컬렉션 구현·검증 이력

문서 갱신: **2026-10-15 · dev `6f0b40a` 기준**.

## 현재 코드의 동작

- 좋아요·열람으로 서로 다른 작품 3점 이상 신호가 쌓이면 테마 생성 대상입니다.
- 컬렉션 탭은 인증된 `POST /api/me/collections/themes/refresh`를 호출합니다. 목표는 분위기가 다른 **2~4개 모음·각 3~8점**이며 실제 개수는 검증된 결과에 따라 적을 수 있습니다. 원본의 1~2개는 최초 버전 설명입니다.
- AI는 실제 후보 작품 ID만 고릅니다. 서버가 근거·작가 다양성·관심 작품 포함·중복을 검사하고 유효한 결과만 제공합니다.
- 캐시는 시간이 지나도 자동 만료하지 않습니다. 좋아요 변경·새 작품 3점 이상 열람·생성 버전 변경 등 의미 있는 신호가 있을 때 최소 30분 간격으로 갱신합니다. 실패 시도에도 간격 제한을 적용합니다.
- AI 테마 상세는 `/collection/auto/{key}`입니다. 사용자가 “내 컬렉션으로 저장”을 선택할 때 일반 모음이 생성되며 10개·30점 한도를 따릅니다.
- 캐시 테이블은 `theme_collection_cache`, 모델 기준 최신 Alembic은 `20261014_0011`입니다. 운영 DB 적용 상태는 서버 담당자가 별도 확인합니다.
- 데모에서는 실제 AI 테마인 것처럼 가짜 결과를 만들지 않습니다. 기존 모음과 AI 생성의 로딩·오류를 구분합니다.

아래 “운영 배포 전·커밋 전”과 153개 테스트는 최초 10/14 작업 기록입니다. 이후 10/15 dev 프론트 배포 기록과 현재 검증 한계는 [배포 안내](../../docs/firebase-vercel.md)·[검증 인덱스](../README.md)를 참고하세요. 이번 문서 갱신에서는 AI 생성이나 운영 DB 쓰기를 실행하지 않았습니다.

# AI 취향 테마 컬렉션

작품을 둘러보고 좋아요하다 컬렉션 탭에 들어오면 AI 테마가 자연스럽게 생긴다.
기존 최근/반복/작가/월별 자동 모음도 계속 표시한다.

## 사용자 동작

- 로그인 사용자가 서로 다른 작품 3점 이상을 조회하거나 좋아요하면 생성 대상이 된다. 질문은 필요 없다.
- 컬렉션 탭 진입 때 AI 테마 1~2개를 준비하고, 모음마다 3~8점을 제안한다.
- 좋아요/누적 조회에서 관심을 읽고, 실제 작품 설명으로 테마를 만든다.
- 각 테마에는 관심 작품이 1점 이상 포함되며, 어울리는 미감상 작품도 섞을 수 있다.
- 후보에 작가가 여럿이면 각 테마에 최소 두 작가를 포함한다. 단순 작가별 모음과 구별한다.
- 카드의 ‘AI 취향’ 배지와 선정 이유를 확인하고, 상세에서 ‘내 컬렉션으로 저장’할 수 있다.
- 직접 저장한 컬렉션은 계정당 최대 10개, 컬렉션당 작품 최대 30점이다.
  AI 모음을 직접 저장한 것도 이 한도에 포함된다. 기존 한도 초과 데이터는 삭제하거나 잘라내지 않고,
  조회·편집·삭제는 허용하며 한도 이내로 줄이기 전에는 새 항목 추가를 막는다.
  최근/반복/작가/월별 자동 모음도 최대 30점을 반환해 그대로 저장할 수 있다.
- AI를 기다리는 동안에도 기존 컬렉션은 표시된다. AI 실패는 별도로 안내한다.
- 데모 모드에서 실제 AI처럼 보이는 가짜 테마를 만들지 않는다.

## 실제 모델 검증

로컬 `.env`의 기존 OpenAI 설정으로, 이전에 사용자가 로그인한 계정의 조회·좋아요 15점과
실제 TiDB 작품 후보 50점을 읽어 생성했다. 운영 DB에는 쓰지 않았다.
최종 생성 결과는 [live-preview.json](live-preview.json)에 있다.

1. **고요한 산수와 자연의 숨결** — 정선·모네, 6점.
   좋아요한 ‘생타드레스의 테라스’와 감상한 산수화를 연결하고 미감상 작품을 포함한다.
2. **바로크의 극적인 인물과 빛의 순간** — 카라바조·렘브란트, 5점.
   ‘엠마오의 만찬’ 등 감상 기록에서 출발해 새로운 인물화로 이어진다.

좋아요/조회 근거 문장은 실제 기록으로 서버가 작성한다. AI는 테마명·공통 감상 경험·선정 순서를 만든다.
출력은 기존 LangChain OpenAI 연동의 구조화된 Pydantic 응답을 사용하며,
[OpenAI 공식 구조화 출력 안내](https://developers.openai.com/api/docs/guides/structured-outputs)를 확인했다.
서버는 실제 후보 ID, 중복 제거, 최소 작품 수, 관심 작품 포함, 여러 작가 연결, 모음 간 중복을 검증한다.
이메일·닉네임·로그인 토큰·비공개 감상문은 모델에 보내지 않는다.

## API 및 캐시

- `POST /api/me/collections/themes/refresh`: 인증 사용자 신호에 따라 캐시 재사용 또는 생성.
- `GET /api/me/collections/auto/theme-1` 및 `theme-2`: 해당 사용자의 캐시를 읽어 기존 상세 계약으로 반환.
- 일반 저장은 기존 `POST /api/me/collections`의 `artwork_ids`를 사용한다.
- `theme_collection_cache`는 사용자별 AI 스냅샷과 생성 시각·신호 지문을 저장한다.
  일반 `collections` 행은 사용자가 저장 버튼을 누를 때만 만든다.
- 감상·좋아요 신호가 같으면 기간 제한 없이 계속 유지한다. 시간이 지났다는 이유로 다시 생성하지 않는다.
  신호가 달라졌을 때만 갱신하며, 생성 간격은 최소 30분이다.
  실패 요청에도 간격 제한을 적용한다. DB의 원자적 UPDATE로 여러 worker의 중복 호출을 막는다.
- 사용자별 외래키 및 인증 사용자 ID로 목록·상세를 분리한다.

## 검증과 배포

- 백엔드 전체: 401개 통과. 사전에 알려진 classifier 모네·세잔 비교 및 docent grounding 2건만 실패.
- 새 생성·캐시·실패 복구·계정 분리·저장 테스트 8개 포함. 기록이 같으면 1년이 지나도 모음과 생성 시각이 유지되는지 확인한다.
- Flutter 분석 이슈 없음, 전체 153개 테스트 통과. AI 카드 → 상세 → 저장 및 10개·30점 한도 경로 포함.
- 신규 Python 파일 Ruff 검사 통과. 마이그레이션의 MySQL SQL 생성 확인.
- Docker 변경 `pubspec.lock`은 원복한다.

**아직 운영 배포하지 않았다.** 배포 순서는 다음과 같다.

1. 운영 DB 백업·현재 revision 확인 후 백엔드에서 `uv run alembic upgrade head` 실행.
   신규 revision은 `20261014_0011`이다.
2. Railway에 백엔드 변경을 반영한다. 기존 `OPENAI_API_KEY`, `ASSISTANT_MODEL`을 사용한다.
3. Vercel에 프론트 변경을 반영한다.
4. 로그인 후 작품 3점을 보고 컬렉션 탭에서 AI 테마·상세·저장을 운영 검증한다.

로컬 구현과 실제 모델 생성 검증까지 완료했으며, 커밋·push·운영 DB 마이그레이션은 하지 않았다.
