# AI 감성 테마 컬렉션

음악 앱의 개인 플레이리스트처럼, 작품을 둘러보고 좋아요하다 컬렉션 탭에 들어오면
‘잔잔한 저녁에 어울리는 그림’ 같은 분위기 컬렉션이 자연스럽게 생긴다.
최근/반복/작가/월별 자동 모음 카드는 컬렉션 탭에서 뺐다(서버 API는 MCP·대화형 컬렉션 요청용으로 유지).

## 사용자 동작

- 로그인 사용자가 서로 다른 작품 3점 이상을 조회하거나 좋아요하면 생성 대상이 된다. 같은 작품의 조회·좋아요는 1점이다.
- 컬렉션 탭 진입 때 분위기가 다른 테마 2~4개를 준비하고, 모음마다 3~8점을 담는다(근거가 부족하면 1개).
- 제목·설명은 분위기·장면·빛·계절·시간으로 짓고, 작가·사조·시대 이름은 쓰지 않는다.
- 각 테마에는 관심 작품이 1점 이상, 작가가 2명 이상 들어가며 어울리는 미감상 작품도 섞인다.
- 카드의 ‘AI 취향’ 배지와 선정 이유(실제 좋아요/감상 기록으로 서버가 작성)를 확인하고,
  상세에서 ‘내 컬렉션으로 저장’할 수 있다. 저장본은 이후 테마가 갱신돼도 바뀌지 않는다.
- 직접 저장한 컬렉션은 계정당 최대 10개, 컬렉션당 작품 최대 30점이다. AI 모음 저장본도 포함된다.
  기존 한도 초과 데이터는 지우거나 자르지 않고 새 추가만 막는다. 동시 요청도 행 잠금으로 한도를 지킨다.
- AI를 기다리거나 실패해도 저장한 컬렉션은 표시되고, 실패는 따로 안내하며 기존 테마를 유지한다.
- 도슨트 채팅은 같은 작품에 세 번째 이상 질문해 답을 받으면 대화당 한 번 ‘컬렉션에 담기’를 제안한다.
  이미 담은 작품은 제외하고, 작가 모음 제안은 하지 않는다.
- 데모 모드에서는 가짜 테마를 만들지 않는다.

## 생성과 검증 방식

- 후보: 관심 작품 전부 + 같은 작가·사조를 우선한 미감상 작품(작가당 최대 4점), 최대 50점.
- 모델: 기존 `collection_assistant.generate()`(LangChain OpenAI 구조화 출력)로 후보 3~5개를 받는다.
- 서버 검증: 실제 후보 ID만, 중복 제거, 3점 이상, 관심 작품 포함, 작가 2명 이상,
  제목에 작가·사조 이름 금지, 설명은 작가·사조 이름이 없는 첫 문장만, 작은 쪽 기준 60% 넘게 겹치면 중복 제외.
  통과한 테마가 2개 미만이면 버려진 이유를 담아 한 번 다시 요청한다(첫 호출 15초 이내, 실패 시 첫 결과 유지).
- 이메일·닉네임·로그인 토큰·비공개 감상문은 모델에 보내지 않는다.
- 한계: 분위기가 작품 설명과 실제로 맞는지는 서버가 판정하지 못한다.
  (예: 설명에 없는 ‘노을·정원’ 분위기를 붙이는 경우가 있다.)

## API 및 캐시

- `POST /api/me/collections/themes/refresh`: 사용자 신호에 따라 스냅샷 재사용 또는 생성.
- `GET /api/me/collections/auto/theme-{n}-{버전8자}`: 캐시의 테마 상세. 테마가 다시 만들어지면 이전 key는 404.
- 일반 저장은 기존 `POST /api/me/collections`의 `artwork_ids`를 사용한다.
- `theme_collection_cache`(사용자당 1행): `themes`, 만들 때의 좋아요·감상 작품 `basis`, 생성·시도 시각.
- 기간 만료 없음. **좋아요가 바뀌거나 새로 본 작품이 3점 이상 쌓였을 때만** 다시 만든다.
  이미 본 작품을 다시 보거나 1~2점 새로 본 것으로는 바꾸지 않는다. 프롬프트·후보 방식이 바뀌면(`GENERATION`) 한 번 다시 만든다.
- 생성 시도는 사용자당 30분에 1회(실패 포함). DB의 원자적 UPDATE로 여러 worker의 중복 호출을 막는다.

## 검증 결과 (2026-10-14)

- 실제 모델(운영 카탈로그 읽기 전용, 가상 관심 기록): 매회 테마 2개, 3~7초.
  예) ‘봄날 아침의 산책길’(고흐·모네·정선 4점), ‘햇살 가득한 아침 연못가’(클림트에서 시작해 모네·정선 미감상 작품 포함),
  ‘빛과 그림자의 극적인 순간’(카라바조·렘브란트).
  이전 프롬프트(작가·사조 위주)로 만든 결과는 [live-preview.json](live-preview.json)에 남아 있다.
- 운영 백업을 복원한 로컬 TiDB에서 API 흐름: 테마 생성·재방문 유지·상세·저장, 10개/30점 한도,
  30점 중복 담기, 도슨트 제안(아직 안 담은 작품은 세 번째에만, 담은 작품은 없음) 모두 통과.
- TiDB v8.5.3에서 동시 요청 6개: 수정 전 15개/35점까지 초과 → 수정 후 정확히 10개/30점.
- 백엔드 `tests` 139개 통과, Ruff 통과, Flutter analyze 이슈 없음.
- 저장소에는 이번 기능 전용 테스트가 없다(검증 스크립트는 임시 위치에서 실행).
